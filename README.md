# HumanityStrongest
Humanity's Strongest - Browser Card Battle Game

## 起動

`index.html` をブラウザで開くか、GitHub Pagesでリポジトリのルートを公開してください。HTML・CSS・JavaScriptのみで動作し、ビルド、サーバー、外部ライブラリ、有料API、AI APIは不要です。

## 試合ルールと操作

1. 「ゲーム開始」で30人から重複なしに6人を抽選し、PLAYERとCPUに3枚ずつ配ります。
2. 上部のCPU手札3枚は表向き、下部のPLAYER手札3枚も表向きです。スマートフォンでもそれぞれ横一列に収まり、長い名前は折り返します。手札には名前・年齢・身長・体重だけを表示し、能力値は表示しません。
3. 中央バトルエリアはCPU（上）→VS→PLAYER（下）。CPU先攻なら出場カードを先に公開し、CPU後攻ならあなたの公開確定後に選んで開始まで裏向きにします。公開手札に出場者を示す印は付けません。
4. 第1ラウンドの先攻はランダム。第2ラウンド以降は前ラウンドの敗者が後攻（勝者が先攻）になります。「あなたが先攻／後攻」を表示します。
5. CPUが先攻なら、先に未使用カードからランダムに1枚を選び、中央上へ公開します。そのカードを確認してからあなたが手札を選び、「このキャラで戦う」で対戦します。
6. あなたが先攻なら、手札を選んで「このカードで決定」で確定します。確定後は選び直せません。その後、CPUが未使用カードからランダムに1枚を選びます。有利なカードを必ず選ぶAIではありません。CPUの選択は伏せたまま、「このキャラで戦う」で公開して対戦します。
7. 未選択時は操作が無効です。公開確定や対戦の連打・直接イベント送出でもCPU選択や勝敗判定をやり直しません。手札は常にプロフィール公開、能力値はリザルトまで非表示です。
8. 使用した両者のカードには「使用済み」と破線を表示し、その試合では再使用できません。「次のラウンドへ」で勝数・使用済みを保ち、次の攻守を決めます。CPU先攻なら新しい公開カードを先に表示し、あなた先攻ならCPUスロットを裏面へ戻します。
9. 最大3ラウンド・2勝先取です。2連勝なら第3ラウンドを行わず終了。引き分けラウンドはありません。「新しい試合」で手札・勝数・使用済み・攻守・結果をリセットします。

CPUの公開手札と秘匿する出場者は区別しています。中央の裏面に出場者の名前・ID・能力値を埋め込みません。ブラウザ内で処理するため、開発者ツールによる内部状態の調査を防ぐ仕組みではありません。

将来の突進用にY軸、CPU `down/+1`、PLAYER `up/-1` の方向属性を維持しています。3回衝突するアニメーションは未実装です。

## 暫定の確率判定

`js/battle.js` に独立した関数と `BALANCE` 設定を用意しています。キャラクターデータ自体は変更していません。

- `calculatePower(character)`：STR・SPD・END・STK・GRP・SUBを同じ重み1で合計します。
- `calculatePlayerWinPercent(playerPower, cpuPower, balance)`：`50 + (PLAYER戦闘力 − CPU戦闘力) × 0.5` を5〜95%に制限します。同じ戦闘力は50%です。
- `resolveRound(playerCard, cpuCard, random)`：0以上1未満の乱数を1回だけ取得し、`乱数 < PLAYER勝率 / 100` ならPLAYER、以上ならCPUの勝ちにします。高い戦闘力でも確定勝利にはなりません。
- 従来の `createCommentary(decision)` / `describeResult(decision)` は保持しています。現在の画面は、独立した `js/story.js` の `generateStory(result)` を使います。勝敗計算には関与しません。

`js/match.js` の `setupTurn()` と `commitPlayerCard()` は攻守順と先攻の確定を管理します。あなた先攻では確定前にCPUカードを選びません。公開後の変更・二重確定は拒否します。勝敗判定に先攻ボーナスは追加していません。

`js/match.js` は判定関数と分離して、配布・ラウンド進行・カード消費・得点・2勝時の終了を管理します。各結果に判定時の6能力値・戦闘力・事前勝率・乱数を保存し、表示やアニメーションで再抽選しません。判定中も状態チェックで多重実行を拒否します。

`js/game.js` の `startBattle()` は開始処理の唯一の入口です。ここから判定と公開を行い、将来の追加演出を接続できます。6つのスクリプトURLは共通の `v=connected-stories-1` で更新しています。

## ラウンドリザルト

開始後にだけ、パワー・スピード・スタミナ・打撃・組み技・関節技を「能力／あなた／CPU」の3列で比較します。差の列はありません。「対戦前の勝率」は維持し、PLAYERは「あなた」、勝ち負けは「勝利／敗北」と表記します。

物語は短いタイトルと150〜250文字程度の自然な3段落で構成します。「序盤・中盤・終盤」の見出しを付けず、具体的な攻撃と対応→反撃と抵抗→生まれた隙を突く決着へつなげます。本文では「あなた」「CPU」を使いません。下に保存済みの「決まり手」も表示します。

`js/combat-styles.js` は正式IDに対応する30人分の演出専用データです。`style`（戦い方）、`techniques`（技候補）、`finishes`（決まり手と動作）、`weakness`（苦手な状況）を管理します。技・決まり手の `stat` は選択の重みに使う既存能力のキーです。候補が複数ある場合、対応能力が高いほど選びやすくします。苦手な状況は各キャラクターの最低能力と指定スタイルに合わせたゲーム上の設定で、職業や国籍から能力を推定しません。CSV・正式プロフィール・能力値は変更しません。この設定を勝敗計算には渡しません。

力の差が20以下なら接戦、90以上なら圧勝を思わせる展開、それ以外は持ち味のぶつかり合いです。低勝率側が勝った場合は番狂わせを優先し、力が近ければ接戦であることも描きます。敗者が攻撃と追撃を仕掛け、勝者が受け方を変えて反撃します。`js/story.js` の動作表現は30人の既存設定に対応し、相手の攻撃の距離（打撃・組み・タックル・引き込み等）と決まり手に必要な体勢を接続します。決まり手ごとに、準備動作・抵抗・隙・最後の技を一続きに用意し、無関係な技をつなげません。カードの先攻後攻は選択順であり、物語の先手とは別です。保存済みの値から受け方や言い回しを切り替え、複数候補がある人物は既存能力を重みに決まり手を選びます。実際の攻防のシミュレーションではなく、画面に「能力と勝敗からふくらませた物語です。」と添えています。

`playRound()` で勝敗確定後に一度だけ生成し、凍結した `result.story` として結果と一緒に保存します。表示・アニメーション・連打では保存した本文を使い、追加の乱数や外部AIは使いません。内部キー・乱数の生値・判定境界・戦闘力合計・計算式は表示しません。次ラウンド・新しい試合では結果を消し、対戦前に能力値を表示しません。

## 正式キャラクターデータ v1

`js/characters.js` の30人は、提供された `data/HumanityStrongest_characters_v1.csv` に準拠します。ID・名前・年齢・身長・体重・6能力値・並び順は変更していません。CSVの保存時にUTF-8/LFへ正規化しBOMを除去しています。年齢は歳、身長はcm、体重はkgです。

## テスト

ゲーム本体には開発用のPython・Node.js・Playwrightは不要です。

- `python tests/characters.test.py`：正式CSVの30人・全項目・並び順とJSデータの一致。
- `node tests/battle.test.cjs`：等重み、暫定式、5/95%制限、50%と抽選境界、番狂わせ、抽選1回、保存結果、6300件の日本語解説の長さ・高い能力との一致・番狂わせ・複数テンプレート・内部情報の非表示。
- `node tests/story.test.cjs`：正式30人の組み合わせなど15,660件で文字数・正式名称・見出しなし3段落・固有技/決まり手・4展開・勝者との整合性・追加抽選なしを確認し、生成1回・保存・再利用、30人全員の設定と苦手状況の根拠、同じ組み合わせでの複数展開、全決まり手候補、重点4対戦の両勝者時の接続も検証。
- `node tests/story-examples.cjs`：重点対戦の勝者違い12件とMMAの関節技2件を生成。実際に読み直した14件と確認内容は [docs/story-review.md](docs/story-review.md) に保存しています。
- `node tests/match.test.cjs`：1000回の6人重複なし抽選、全30人の登場、再使用禁止、2連勝・3戦決着、多重実行禁止、先攻ランダム・敗者後攻・公開確定後のCPUランダム選択・確定後変更禁止。
- `node tests/deal.test.cjs`：最小DOMで公開手札3枚、選択・中央反映・結果表示、ラウンド進行・使用済み・試合終了・新しい試合を検証。
- `node tests/mobile.browser.cjs`：開発環境のPlaywrightとChromiumで320/375/390/430/768/1280pxを検証します。長い名前・横3枚・縦配置・プロフィール、事前能力値非表示、リザルトの全値と保存内容の一致、タップ/連打/アニメーション中の抽選回数、次ラウンド・2勝終了を確認します。`CHROMIUM_PATH` で実行ファイルを指定可能です。

ブラウザテストはローカルの実ファイルを直接読み込み、ネットワークやテスト用サーバーを使いません。実機SafariやGitHub Pagesの公開配信・キャッシュ状態の確認は含みません。スクリプトとHTMLの整合性が変わる更新では、全スクリプトURLの版番号を合わせて更新してください。
