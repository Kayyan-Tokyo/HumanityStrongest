# HumanityStrongest
Humanity's Strongest - Browser Card Battle Game

## 起動

`index.html` をブラウザで開くか、GitHub Pagesでリポジトリのルートを公開してください。HTML・CSS・JavaScriptのみで動作し、ビルド、サーバー、外部ライブラリ、有料API、AI APIは不要です。

## スマートフォンUI

ラウンド/勝数は1行、先攻後攻の案内は枠なしの小さなテキストに整理しています。スマホでは中央エリアと未選択枠の余白を縮め、CPU・あなたの手札各3枚を確認しやすくしました。手札カードの大きさ・プロフィール表示と移動処理は維持しています。修正前後のスクリーンショットと測定値は [docs/mobile-ui.md](docs/mobile-ui.md) を参照してください。

## 1タップ操作とバトル演出

手札を1回タップすると、そのカードで確定します。確定・対戦開始ボタンはありません。カードは150msで浮き、400msで中央へ移動します。CPU先攻は先にカードを配置し、その後にあなたが選べます。あなた先攻は移動完了後に既存のCPU選択処理を呼び、CPUカードも自動配置します。

両カードがそろったら既存の勝敗判定を1回だけ実行し、保存済みの結果で対峙→突進→短いフラッシュ/振動→敗者の燃焼→WIN→既存リザルトの順に進みます。燃焼は1000msでclip-pathの上辺を0%から100%へ動かし、上から下へ消します。同じ位置を進む赤〜オレンジの境界と、乱数を使わない小さな火の粉を添えています。勝者は残り、WINには「あなた」または「CPU」を表示します。

アニメーション中は手札・新しい試合・次ラウンドをロックし、ページを自動スクロールしません。「演出をスキップ」またはEscで省略できます。ページ非表示や動きを抑える設定への切り替えでも待機を解除し、確定結果へ進みます。reduced-motion/API未対応では動きを省略して同じ結果を表示します。各アニメーションにはタイムアウトもあります。

実装内容と動作確認画像は [docs/one-tap-battle.md](docs/one-tap-battle.md) を参照してください。

## 試合ルール

- 30人から重複なしに6人を選び、両者へ3枚ずつ配ります。手札は常に表向きで、名前・年齢・身長・体重を表示します。
- 第1ラウンドの先攻はランダム。第2ラウンド以降は前ラウンドの勝者が先攻、敗者が後攻です。CPU後攻はあなたの選択が確定した後、未使用カードからランダム選択します。
- 使用済みカードは再使用不可。最大3ラウンド・2勝先取で、2連勝なら第3ラウンドを行いません。
- リザルトの「次のラウンドへ」で残りの手札を選び、「新しい試合」でリセットします。


CPUの公開手札と秘匿する出場者は区別しています。中央の裏面に出場者の名前・ID・能力値を埋め込みません。ブラウザ内で処理するため、開発者ツールによる内部状態の調査を防ぐ仕組みではありません。

突進はY軸でCPUを下、あなたを上へ移動させます。現在の衝突は各ラウンド1回です。

## 暫定の確率判定

`js/battle.js` に独立した関数と `BALANCE` 設定を用意しています。キャラクターデータ自体は変更していません。

- `calculatePower(character)`：STR・SPD・END・STK・GRP・SUBを同じ重み1で合計します。
- `calculatePlayerWinPercent(playerPower, cpuPower, balance)`：`50 + (PLAYER戦闘力 − CPU戦闘力) × 0.5` を5〜95%に制限します。同じ戦闘力は50%です。
- `resolveRound(playerCard, cpuCard, random)`：0以上1未満の乱数を1回だけ取得し、`乱数 < PLAYER勝率 / 100` ならPLAYER、以上ならCPUの勝ちにします。高い戦闘力でも確定勝利にはなりません。
- 従来の `createCommentary(decision)` / `describeResult(decision)` は保持しています。現在の画面は、独立した `js/story.js` の `generateStory(result)` を使います。勝敗計算には関与しません。

`js/match.js` の `setupTurn()` と `commitPlayerCard()` は攻守順と先攻の確定を管理します。あなた先攻では確定前にCPUカードを選びません。公開後の変更・二重確定は拒否します。勝敗判定に先攻ボーナスは追加していません。

`js/match.js` は判定関数と分離して、配布・ラウンド進行・カード消費・得点・2勝時の終了を管理します。各結果に判定時の6能力値・戦闘力・事前勝率・乱数を保存し、表示やアニメーションで再抽選しません。判定中も状態チェックで多重実行を拒否します。

`js/game.js` の `selectCard()` が1タップ進行の入口です。両カード配置後に判定し、`battleEffects()` に保存結果を渡し、演出後に `finishRound()` でリザルトを表示します。6つのスクリプトURLは共通の `v=one-tap-battle-1` で更新しています。

## ラウンドリザルト

開始後にだけ、パワー・スピード・スタミナ・打撃・組み技・関節技を「能力／あなた／CPU」の3列で比較します。差の列はありません。「対戦前の勝率」は維持し、PLAYERは「あなた」、勝ち負けは「勝利／敗北」と表記します。

物語は短いタイトルと150〜250文字程度の自然な3段落で構成します。「序盤・中盤・終盤」の見出しを付けず、具体的な攻撃と対応→反撃と抵抗→生まれた隙を突く決着へつなげます。冒頭で両者の正式名称を出し、以降は「剣闘士」「大戦期の米兵」などの重複しない短縮名を使います。本文では「あなた」「CPU」「相手」「両者」「彼」を使いません。下に保存済みの「決まり手」も表示します。

`js/combat-styles.js` は正式IDに対応する30人分の演出専用データです。`style`（戦い方）、`techniques`（技候補）、`finishes`（決まり手と動作）、`weakness`（苦手な状況）を管理します。技・決まり手の `stat` は選択の重みに使う既存能力のキーです。候補が複数ある場合、対応能力が高いほど選びやすくします。苦手な状況は各キャラクターの最低能力と指定スタイルに合わせたゲーム上の設定で、職業や国籍から能力を推定しません。CSV・正式プロフィール・能力値は変更しません。この設定を勝敗計算には渡しません。

力の差が20以下なら接戦、90以上なら圧勝を思わせる展開、それ以外は持ち味のぶつかり合いです。低勝率側が勝った場合は番狂わせを優先します。カードの先攻後攻は選択順であり、物語の先手とは別です。決まり手は勝者の既存候補から、既存能力を重みに先に選びます。

`js/story.js` に物語専用の軽量な状態管理を追加しています。距離3種類・両者の姿勢3種類・つかむ手を記録し、寝技の上下と決着済みかも確認します。動作ごとの前提条件を検査し、手をほどく・近づく・組み付く動作を必要に応じて本文にも挟みます。本文はこの同じ動作列から作るため、状態だけを無言で変更しません。状態の再生検証や文字量の条件に合わない候補は全文を破棄し、同じ決まり手で別の展開を最初から組み立てます。新たな乱数は取得しません。

投げには組み付きと崩れ、打撃には自由な手と届く距離、関節技には寝技、絞め技には上を取る動作が必要です。膝蹴りは引き寄せる筋と、いったん離して再接近を待つ筋があります。KO後の行動や、地面から無説明に立つ動作は拒否します。保存する `result.story.scene` の前後状態・動作列は内部データで、画面には出しません。ダメージ・命中率・勝敗をシミュレーションする処理は追加していません。

文章改善フェーズの修正前後と残る課題は [docs/story-final-review.md](docs/story-final-review.md) に記録しています。文章の追加改善はいったん保留し、現在はカード演出を開発しています。

同じ人物が同じ段落で続けて動く場合だけ主語を省略し、人物・段落が変われば戻します。手首や肘など動作を具体化し、本文の感嘆符は決着の1回までに制限します。

状態管理の設計と導入時の改善前後の比較は [docs/story-state.md](docs/story-state.md)、読み直した30件は [docs/story-review.md](docs/story-review.md) を参照してください。画面の「能力と勝敗からふくらませた物語です。」は維持しています。

`playRound()` で勝敗確定後に一度だけ生成し、凍結した `result.story` として結果と一緒に保存します。表示・アニメーション・連打では保存した本文を使い、追加の乱数や外部AIは使いません。内部キー・乱数の生値・判定境界・戦闘力合計・計算式は表示しません。次ラウンド・新しい試合では結果を消し、対戦前に能力値を表示しません。

## 正式キャラクターデータ v1

`js/characters.js` の30人は、提供された `data/HumanityStrongest_characters_v1.csv` に準拠します。ID・名前・年齢・身長・体重・6能力値・並び順は変更していません。CSVの保存時にUTF-8/LFへ正規化しBOMを除去しています。年齢は歳、身長はcm、体重はkgです。
