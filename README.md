# HumanityStrongest
Humanity's Strongest - Browser Card Battle Game

## 起動

`index.html` をブラウザで開くか、GitHub Pagesでリポジトリのルートを公開してください。HTML・CSS・JavaScriptのみで動作し、ビルド、サーバー、外部ライブラリ、APIは不要です。

## 対戦準備の操作

1. 「ゲーム開始」で30人から重複なしに8人を抽選し、プレイヤーとCPUに4枚ずつ配ります。
2. CPU手札は画面上部の横4枚の裏面、プレイヤー手札は下部の横一列4枚です。スマートフォンでも両者の4枚を画面幅内に収め、横スクロールは使いません。両者の手札の間に、左PLAYER・中央VS・右CPUのバトルエリアを表示します。スマートフォンでも左右の配置を維持します。
3. プレイヤーのカードは名前・年齢・身長・体重のみ表示します。タップ、またはTabでフォーカスしてEnter/Spaceで1枚選択します。同じカードで解除、別のカードで切り替えます。選択中のカードは中央左のPLAYER枠にも表示します。
4. 「このキャラで戦う」で中央バトルエリアを対戦準備状態にします。上下の手札は表示したまま、選び直しと再配布を一時的に無効にします。未選択では進めません。CPUの出場カードは配布時に内部で決まり、この段階では裏向きです。
5. 「バトル開始」でCPUの出場カードを公開します。短い回転演出があり、動きを減らす設定では省略します。勝敗計算や本格的なバトルは未実装です。
6. 公開後の「手札に戻る」では、両者の手札・プレイヤーの選択・CPUの出場者を保持します。CPUカードを裏向きに戻して手札の選択操作を再開しますが、CPUの出場者は変わりません。
7. 手札画面の「配り直す」だけが両者の手札とCPUの出場者を再抽選し、プレイヤーの選択を解除します。前回の人物が再登場することはあります。

CPUの未公開情報を裏面のDOM・ラベル・data属性へ埋め込みません。すべてブラウザ内で処理するゲームのため、開発者ツールによる内部データの調査を防ぐ仕組みではありません。

バトルエリアの `.battle-side--player` は `data-attack-direction="right"` と `--attack-direction: 1`、`.battle-side--cpu` は `data-attack-direction="left"` と `--attack-direction: -1` を持ちます。将来は各枠内のカードを中央へ向けて移動させる構成です。今回は配置と既存のCPU公開演出のみで、突進演出・勝敗計算は実装していません。

## 正式キャラクターデータ v1

`js/characters.js` の `window.CHARACTERS` は、提供された `HumanityStrongest_characters_v1.csv` に基づく正式キャラクター30人です。照合元のCSVを `data/HumanityStrongest_characters_v1.csv` に保存しています（UTF-8・LFに正規化し、BOMを除去）。ID・名前・年齢・身長・体重・6能力値・並び順はCSVに従い、独自の補正や人物の追加は行っていません。

`id` は一意、`age` は歳、`height` はcm、`weight` はkg、`stats` はSTR・SPD・END・STK・GRP・SUBの数値です。能力値は手札と対戦準備画面・CPU公開時の画面やアクセシブル名には出力しません。手札・出場カードのオブジェクト内には保持し、将来の勝敗計算やリザルトに利用できます。

`js/match.js` は両者の配布とCPU出場カード選択、`js/game.js` は画面遷移・選択・公開を担当します。戻る操作では配布関数を呼びません。現在のスクリプトURLの版番号は `v=compact-copy-1` です。

## テスト

開発環境で `python tests/characters.test.py` によりCSV全30人の全11項目・並び順・型を実JSデータと照合できます。任意のCSVパスを引数に指定して元の添付CSVとも照合できます。続いて `node tests/deal.test.cjs` を実行してください。外部テストライブラリは不要です。30人のデータ構造、1000回の8人重複なし抽選、能力値保持、CPUカードの所属、乱数の両端、不正データの拒否、画面切り替え、未選択時の制御、プロフィール表示、能力値非表示、CPU情報の非表示、選択・解除・切り替え、公開と再入場、戻る時の手札・選択・CPU出場者保持、再配布時のリセットを検証します。

このテストは最小DOMによるロジック検証で、実ブラウザのレイアウトやアニメーションの目視確認を代替しません。Node.jsはゲームの実行には不要です。

## スマートフォン表示の回帰テスト

開発環境にPlaywrightとChromiumがある場合、`node tests/mobile.browser.cjs` を実行できます。必要に応じて `CHROMIUM_PATH` で実行ファイルを指定してください。Playwrightは開発時の表示検証にだけ使用し、ゲーム本体には読み込まず、実行時依存も追加しません。

320・375・390・430・768・1280pxの幅で実ファイルのHTML/CSS/JavaScriptをChromiumへ読み込み、CPU裏面4枚の横並びと画面内への収まり、プレイヤー横一列4枚と長い名前の折り返し・プロフィールの欠落なし、中央のPLAYER左・VS中央・CPU右とその上下に手札があること、横はみ出しの有無、能力値の視覚・アクセシビリティ上の非表示、選択・対戦準備・公開・戻る際の状態保持・再配布を検証します。JavaScript未読込時にも静的なCPU裏面4枚が表示されることを確認します。ネットワークやテスト用サーバーは使いません。

### 表示不具合の調査と更新時の注意

PR #4のHTMLとPR #3の旧 `js/game.js` を組み合わせると、CPU手札の要素数が0・高さが0になり、プレイヤーの能力値が表示されることを375pxの実ブラウザで再現しました。最新mainのHTMLとJavaScriptの組み合わせでは再現しませんでした。これは古いJavaScriptキャッシュやデプロイ途中のファイル混在で起こり得る症状であり、実機のキャッシュ状態までは断定していません。

対策として、PR #5では3つのJavaScript URLに同じ版番号 `v=cpu-hand-2` を付け、旧無版番号URLのキャッシュと分離しています。以後、スクリプトを更新してHTMLとの整合性が変わる場合は全URLの版番号を一緒に更新してください。CPU裏面4枚はHTMLにも用意し、高さと4列を明示しています。手札・出場カード内の旧 `.card-stats` はCSSでも非表示にし、現在のJavaScriptは能力値DOMを生成しません。能力値データは変更していません。

実ブラウザテストはローカルの実ファイルを読み込んだ検証であり、公開先GitHub Pagesのデプロイ状態や実機Safariのキャッシュ状態を確認するものではありません。
