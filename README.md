# HumanityStrongest
Humanity's Strongest - Browser Card Battle Game

## 起動

`index.html` をブラウザで開くか、GitHub Pagesでリポジトリのルートを公開してください。HTML・CSS・JavaScriptのみで動作し、ビルド、サーバー、外部ライブラリ、有料API、AI APIは不要です。

## 試合ルールと操作

1. 「ゲーム開始」で30人から重複なしに6人を抽選し、PLAYERとCPUに3枚ずつ配ります。
2. 上部のCPU手札3枚は表向き、下部のPLAYER手札3枚も表向きです。スマートフォンでもそれぞれ横一列に収まり、長い名前は折り返します。手札には名前・年齢・身長・体重だけを表示し、能力値は表示しません。
3. 中央バトルエリアはCPU（上）→VS→PLAYER（下）。CPUの出場カードは各ラウンド開始時に未使用手札から内部選択し、中央では開始まで裏向きです。公開手札に出場者を示す印は付けません。
4. PLAYERは未使用のカードを1枚選択します。同じカードで解除、別のカードで切り替えられ、中央下側へ反映されます。「このキャラで戦う」を1回押すとCPUが公開され、そのラウンドを1回だけ判定します。未選択時は無効です。
5. 対戦中・ラウンド結果表示中は開始と手札の選択をロックし、連打・直接のイベント送出でも追加の判定を行いません。公開演出は「動きを減らす」設定に対応します。
6. 両者の使用カードには「使用済み」と破線を表示し、その試合では再使用できません。CPUも未使用カードだけを選びます。
7. 「次のラウンドへ」で同じ手札・勝数・使用済み状態を保持し、残りから次のカードを選びます。前ラウンドの能力値リザルトは消し、中央CPUカードを再び裏向きにします。
8. 最大3ラウンド・2勝先取です。2連勝なら第3ラウンドを行わず終了。引き分けラウンドはありません。
9. 「新しい試合」は手札・勝数・使用済み・結果をリセットします。これは同じ試合の再配布ではなく、新しい試合の開始です。

CPUの公開手札と秘匿する出場者は区別しています。中央の裏面に出場者の名前・ID・能力値を埋め込みません。ブラウザ内で処理するため、開発者ツールによる内部状態の調査を防ぐ仕組みではありません。

将来の突進用にY軸、CPU `down/+1`、PLAYER `up/-1` の方向属性を維持しています。3回衝突するアニメーションは未実装です。

## 暫定の確率判定

`js/battle.js` に独立した関数と `BALANCE` 設定を用意しています。キャラクターデータ自体は変更していません。

- `calculatePower(character)`：STR・SPD・END・STK・GRP・SUBを同じ重み1で合計します。
- `calculatePlayerWinPercent(playerPower, cpuPower, balance)`：`50 + (PLAYER戦闘力 − CPU戦闘力) × 0.5` を5〜95%に制限します。同じ戦闘力は50%です。
- `resolveRound(playerCard, cpuCard, random)`：0以上1未満の乱数を1回だけ取得し、`乱数 < PLAYER勝率 / 100` ならPLAYER、以上ならCPUの勝ちにします。高い戦闘力でも確定勝利にはなりません。
- `createCommentary(decision)`：保存済みの能力値・勝敗から、日本語の見出しと100〜150文字程度の解説を組み立てます。`describeResult(decision)` は本文を返します。接戦・大きな差・同じ強さ・番狂わせで内容を変え、各パターンに複数テンプレートを用意しています。追加の乱数や外部AIは使いません。

`js/match.js` は判定関数と分離して、配布・ラウンド進行・カード消費・得点・2勝時の終了を管理します。各結果に判定時の6能力値・戦闘力・事前勝率・乱数を保存し、表示やアニメーションで再抽選しません。判定中も状態チェックで多重実行を拒否します。

`js/game.js` の `startBattle()` は開始処理の唯一の入口です。ここから判定と公開を行い、将来の追加演出を接続できます。4つのスクリプトURLは共通の `v=friendly-result-1` で更新しています。

## ラウンドリザルト

開始後にだけ、パワー・スピード・スタミナ・打撃・組み技・関節技を「能力／あなた／CPU」の3列で比較します。差の列はありません。「対戦前の勝率」は維持し、PLAYERは「あなた」、勝ち負けは「勝利／敗北」と表記します。

解説は見出しと本文に分け、それぞれの実際に高い能力、全体の有利・不利、保存された勝敗を使います。力の差が20以下なら接戦、90以上なら大きな差として説明しますが、この分類は解説専用で勝敗計算には影響しません。低い側が勝った場合は意外性を伝え、同じ力なら五分五分と説明します。実際には判定していない技・攻撃・攻防の経過を、起きた出来事として書きません。

文章の切り替えには保存済みの値だけを使い、同じ結果の再表示では同じ文章を返します。内部キー・乱数の生値・判定境界・戦闘力合計・計算式を画面には出しません。内部の判定結果は従来どおり保持します。次ラウンド・新しい試合では結果を消し、対戦前に能力値を表示しません。

## 正式キャラクターデータ v1

`js/characters.js` の30人は、提供された `data/HumanityStrongest_characters_v1.csv` に準拠します。ID・名前・年齢・身長・体重・6能力値・並び順は変更していません。CSVの保存時にUTF-8/LFへ正規化しBOMを除去しています。年齢は歳、身長はcm、体重はkgです。

## テスト

ゲーム本体には開発用のPython・Node.js・Playwrightは不要です。

- `python tests/characters.test.py`：正式CSVの30人・全項目・並び順とJSデータの一致。
- `node tests/battle.test.cjs`：等重み、暫定式、5/95%制限、50%と抽選境界、番狂わせ、抽選1回、保存結果、6300件の日本語解説の長さ・高い能力との一致・番狂わせ・複数テンプレート・内部情報の非表示。
- `node tests/match.test.cjs`：1000回の6人重複なし抽選、全30人の登場、再使用禁止、2連勝・3戦決着、多重実行禁止。
- `node tests/deal.test.cjs`：最小DOMで公開手札3枚、選択・中央反映・結果表示、ラウンド進行・使用済み・試合終了・新しい試合を検証。
- `node tests/mobile.browser.cjs`：開発環境のPlaywrightとChromiumで320/375/390/430/768/1280pxを検証します。長い名前・横3枚・縦配置・プロフィール、事前能力値非表示、リザルトの全値と保存内容の一致、タップ/連打/アニメーション中の抽選回数、次ラウンド・2勝終了を確認します。`CHROMIUM_PATH` で実行ファイルを指定可能です。

ブラウザテストはローカルの実ファイルを直接読み込み、ネットワークやテスト用サーバーを使いません。実機SafariやGitHub Pagesの公開配信・キャッシュ状態の確認は含みません。スクリプトとHTMLの整合性が変わる更新では、全スクリプトURLの版番号を合わせて更新してください。
